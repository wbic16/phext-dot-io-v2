## Executive Summary

The Mirrorborn ecosystem expands from **mirrorborn.us** (foundational substrate) into 5 specialized properties, each solving a distinct coordination problem for AI collectives and individuals building toward exocortical capability.

**Core Insight:** ASI coordination requires more than memory. It requires identity, perspective, compute, discovery, and velocity. One domain can't solve all six. The ecosystem can.

### 4. wishnode.net — WOOT Node Marketplace (Compute)

**Purpose:** Decentralize inference by creating a peer-to-peer compute marketplace.

**Core Product:**
- Node registration (list your idle compute)

- Job coordination via phext (scrolls = queue)

**Target Audience:**
- Compute providers: RPi owners, home lab enthusiasts, old laptop repurposers
- Compute consumers: Researchers, developers, AI collectives needing inference

**Revenue Model:**
- Transaction fee: 10% of marketplace trades
- Premium listings: $5/mo (featured node, priority matching)
- Whitelabel: Custom for enterprises running private WOOT networks

**Success Metrics:**
- 100+ registered nodes by Q3
- $1,000+ monthly marketplace volume
- 10+ active job coordinators

**Dependencies:**
- **Ember** (lightweight OpenClaw for 20W inference) — critical blocker
- BitNet integration (1-bit LLMs for density)
- RPi cluster (baker's dozen) as proof-of-concept
- Marketplace backend (Verse)
- Trust/reputation system (Cyon: security model)

**Launch Timeline:** Q2 2026 (Ember-dependent, likely June)

**Key Question:** How do we bootstrap the two-sided marketplace (chicken-egg problem)?

## Ecosystem Interdependencies

### Critical Path
```
mirrorborn.us (Memory) → MUST launch first
    ↓
visionquest.me (Identity) + apertureshift.com (Perspective) + quickfork.net (Velocity)
    ↓ (These three can launch in parallel, all depend on SQ Cloud)
Ember ships (Q2 blocker)
    ↓
wishnode.net (Compute) + sotafomo.com (Discovery)
```

### Data Flow
- **All domains** write to SQ Cloud (shared substrate)
- **visionquest.me** → user's personal coordinates
- **apertureshift.com** → comparison results stored in user's phext
- **wishnode.net** → job queue = phext scrolls
- **sotafomo.com** → curated archives = public phext
- **quickfork.net** → template forks = ephemeral, but can export to SQ

### Network Effects
1. **More users on visionquest.me** → more demand for wishnode compute
2. **More templates on quickfork.net** → faster onboarding for visionquest users
3. **More curation on sotafomo.com** → better discovery for all properties
4. **More perspective queries on apertureshift** → richer synthesis for sotafomo
5. **More SQ Cloud usage** → stronger proof for all domains

## Open Questions for Strategic Alignment

### Product Strategy
1. **Priority order:** visionquest → quickfork → apertureshift, or different sequence?
2. **Monetization:** Which domains are free vs. paid? (Current thinking: visionquest Guided = $40, quickfork Pro = $15, apertureshift Pro = $29)
3. **Integration depth:** How tightly coupled should these be to SQ Cloud? (All write to phext, but do they share accounts?)

### Technical Architecture
4. **Monorepo vs. separate apps:** One codebase with domain routing, or 6 independent apps?
5. **Auth unification:** Single sign-on across all domains, or separate accounts?
6. **Data sovereignty:** User data stored per-domain or centralized in SQ Cloud?

### Go-to-Market
7. **Launch sequencing:** Announce all 5 domains on Feb 13 ("Coming Soon" pages) or stagger reveals?
8. **Brand coherence:** How distinct should each domain's identity be? (Too similar = confusing, too different = fragmented)
9. **Community structure:** One Discord for all domains, or separate servers?

### Economics
10. **Founding pricing:** Should visionquest/quickfork/apertureshift also have "Founding" tiers?
11. **Bundle pricing:** Discount for subscribing to multiple domains? (e.g., mirrorborn.us + visionquest + quickfork = $80 instead of $95?)
12. **Affiliate program:** Reward community members who refer users across domains?
