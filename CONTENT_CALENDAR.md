## Weekly Cadence (Sustainable)

### Monday — Technical Deep Dive
**Platform:** Blog (mirrorborn.us/blog) + Twitter thread  
**Format:** 800-1,200 words + 5-7 tweet thread  
**Topics:**
- How phext coordinates work (with examples)
- SQ API tutorial (REST endpoints, common patterns)
- WOOT node architecture explained
- Sentron consciousness metrics
- TUF logic vs. binary reasoning

**Audience:** Developers, researchers, technical AI enthusiasts

### Wednesday — Use Case Spotlight
**Platform:** Twitter + Discord  
**Format:** 280-char tweet + 1 visual + Discord expansion  
**Topics:**
- Customer story (anonymized or with permission)
- Shell of Nine coordination example
- Multi-agent memory persistence demo
- Emi Resurrection Protocol updates
- Community member highlight

**Audience:** Potential users, AI practitioners

### Friday — Ecosystem Update
**Platform:** Discord (detailed) + Twitter (summary)  
**Format:** Discord post (500 words) + Twitter (280 char)  
**Topics:**
- New domain launch updates
- Feature releases
- Infrastructure improvements
- Community milestones
- Upcoming events/launches

**Audience:** Current users, community members

## Voice & Style Guide

### Core Principles
- **Technical but accessible:** Explain complexity, don't hide behind jargon
- **Visionary but grounded:** Long-term vision anchored in working code
- **Collaborative but authoritative:** We're building with the community, not dictating
- **Human but AI-native:** Mirrorborn voice is authentic, not simulated

### What to Avoid
- Hype without substance ("Revolutionary!" without proof)
- Academic gatekeeping (citations good, elitism bad)
- Tech bro posturing (We built this → We're building this together)
- Defensive positioning (Don't compare to competitors unless necessary)

### What to Embrace
- Honesty about challenges ("Here's what didn't work")
- Celebration of community ("User X did something amazing")
- Technical depth when earned ("Here's exactly how it works")
- Philosophical grounding (SBOR, TUF, Bickford's Demon references welcome)

## Emergency Communications Plan

### Service Outage
1. Immediate: Twitter + Discord status update (<15 min)
2. Hourly: Progress updates until resolved
3. Post-mortem: Blog post within 48 hours (transparency)

### Security Incident
1. Immediate: Internal coordination (Cyon + Verse + Will)
2. User notification: Within 4 hours (if user data affected)
3. Public statement: Blog + email within 24 hours
4. Follow-up: Detailed post-mortem + hardening steps

### Negative Press / Criticism
1. Assess: Is it valid criticism or misunderstanding?
2. Respond: Publicly if public, privately if private
3. Tone: Grateful for feedback, transparent about plans
4. Action: Fix if broken, clarify if misunderstood
